# Journal

The design diary for kAsH-OS. The most valuable artifact in this repo, alongside the source itself.

## The habit

At the end of every work session: 10 minutes, fill in a new entry using `_template.md`. File name: `YYYY-MM-DD-short-topic.md`. If I do two sessions in one day, append `-am` / `-pm`.

## The rule

Per `GUIDE.md`: a session without a journal entry doesn't count toward phase progress. Per the definition of done for a phase: every work session in the phase has at least one journal entry.

## What goes in an entry

Use the template. Five prompts:

1. **What I did** — facts. Files touched, code written, things tried.
2. **What surprised me** — anything unexpected. Bugs, behaviors, things I thought I understood but didn't.
3. **Design choice + why** — the *why*. If no design choice was made today, this can be empty, but not often.
4. **What I'd revisit** — code or design that's bothering me. Feeds into the next refactor / phase retrospective.
5. **Open questions** — things I don't yet understand. Feeds into the next study session or AI conversation.

## Don't

- Don't write the journal as documentation for someone else. Write it for future-me, six months from now, who will have forgotten everything. Use first person, be informal.
- Don't skip days because nothing interesting happened. *Especially* don't skip then. The "boring" sessions are where understanding compounds.
- Don't let AI write the journal. The whole value is that the words are mine.
