# Concepts

This folder is for **my own** concept notes — written in my own words, after I've struggled with a topic and built something that uses it.

## The rule

> AI is for review, not authorship.

Concept notes here must be drafted by me. AI may then critique, point out misunderstandings, or suggest things I've missed. But the words and structure must be mine.

This folder is deliberately empty at the start of the project. It fills up as I work through phases. By the end of the project, it should be the textbook I would have wanted to read at the start.

## Format

- One file per concept. File name: `<short-name>.md` (e.g., `risc-v-trap-delivery.md`, `sv39-translation.md`, `spinlock-semantics.md`).
- No template. Write whatever structure helps me learn.
- Include diagrams (ASCII is fine), worked examples, and links back to the spec sections that ground the concept.
- Cross-link to the journal entry where I first hit the topic, if useful.

## What this folder is NOT

- Not a place to copy-paste the RISC-V spec. The spec is the spec.
- Not a place to dump AI explanations. Those go nowhere — into the conversation, not the repo.
- Not reference material for anyone else. It's for me.

## When to add a note

- After completing a phase's central concept.
- When I've debugged a problem that taught me something I didn't have the words for before.
- When a quarterly retrospective surfaces a pattern I want to record permanently.

## When to revise a note

- When my understanding has changed materially. Don't delete the old version — revise in place and commit, so git history shows my understanding evolving.
